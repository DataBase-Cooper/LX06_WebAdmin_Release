# AI 二次开发交接

先确认设备型号、运行固件版本和实际上传的脚本 SHA-256。从 Release 标签建一个工作分支，再按 [源码地图](SOURCE_MAP.md) 找入口。

| 修改目标 | 推荐验证 |
| --- | --- |
| Windows 刷机与驱动界面 | 跑 Go 测试，用 --headless 核对两种镜像、版本和校验。 |
| 设备网页或接口 | 重编 Web88 的 C 服务，先在 QEMU 检查声明和 API，再做限域真机测试。 |
| 小智断句、播放或打断 | 重编 ARM 客户端并嵌入脚本。分别测正常播完、打断、旧音频丢弃及同一会话的新问题。 |
| 豆包打断 | 分开测打断词、人声、纯回声和打断后的完整上行。 |
| 本地唤醒 | 区分训练录音、独立正样本、非唤醒负样本和弱音测试。检查模型兼容。 |
| 账号脚本字段 | 优先改脚本的扩展声明。通用字段、保存和设备接口由固件负责。 |
| 升级包 | 验证解包清单、OTA 校验、实机切槽和首次启动。 |

向 AI 提供标签、模块路径、复现步骤和必要的脱敏日志。账号令牌、绑定码、录音和个人 DATA 保留在本地。重发版本时，让源码清单、嵌入载荷和最终文件哈希对应。

## rc42 入口

小智的任务状态、查询和播放前让出麦克风分别见 `task_poll.c`、`main.c` 和 `scripts/xz_mcp_task_state.sh`。默认换气结束词和自动查询开关在脚本声明与脚本构建器中。独立 MCP 入口是 `runtime/model-adapter/mcp_task_watch.sh`。检测字段显隐问题时先用非服务专属字段运行通用 Web88 回归。
