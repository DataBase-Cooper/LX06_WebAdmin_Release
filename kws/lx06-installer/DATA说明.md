# V20261029.1-rc9：MFCC 与 DATA 布局

这是按用户要求交付的人工验收版，尚未完成清 DATA 后刷机验收。系统程序和资源放只读固件，DATA 保存必须跨重启保留的数据；不以“目录只有一个文件”为目标删除官方配网、密码或故障恢复状态。

## 只读固件

- `/usr/lib/lx06/wakeword/`：MFCC 可执行文件、监听/录词脚本和提示音。
- `/usr/lib/lx06/xiaoai/`：音频订阅、官方会话仲裁组件。
- `/usr/sbin/lx06webd`、`/usr/sbin/dropbear`、Web 页面和系统服务。
- `/usr/bin/lx06-dialog-light`、`/usr/include/lx06/dialog-light.h`、`/usr/share/lx06/dialog-light-api.md`：固定对话灯光接口和开发说明。
- `/lx06-init.sh`：用户启动入口的初始模板，首次启动复制到 `/data/init.sh`。

MFCC 固定为此前 .166 实测的 `mfcc-lifter32 v8`，398,600 字节。音箱及 rc4 至 rc9 中的检测程序 SHA256 均为：

`fc9fa071548b3d93feecfef39ec02f692f479a131c151cdb938ace1bec97f454`

新包不预装小智/豆包、测试探针、用户录音、模型或阈值。两份个人脚本随 PC 刷机包附带，通过 Web88 分别部署，顺序不限；私人豆包密钥只在该上传脚本内，不放系统镜像。`init.sh` 不再启动第二份系统唤醒服务；MFCC 由固件 S62 服务启动。Web 录词只调用固件脚本，不优先执行旧 DATA 热更新副本。

## DATA 中的必要内容

| 类别 | 路径/内容 | 保留原因 |
| --- | --- | --- |
| 用户启动入口 | `/data/init.sh` | 用户脚本唯一开机入口；Web 维护常驻程序块，用户修改需保留。 |
| SSH89/Web88 共用密码 | `/data/lx06-ssh.conf`、`/data/etc/shadow` | Web 修改密码后，两端即时生效，普通重启后保留。只读固件不能保存改后的密码。 |
| SSH 主机身份和配置 | `/data/etc/dropbear/`、`/data/etc/config/dropbear` | 保留主机密钥、端口及认证配置；避免普通重启改变主机身份。 |
| 刷机/恢复出厂标记 | `lx06-ssh-seq`、`ssh_en`、`.lx06-ssh-*` 等 | 现有认证装配链用来区分首次启动、普通重启和恢复出厂，本版保留。 |
| 用户录词后产生 | `/data/wakeword/wakeword.conf`、`models/`、`recs/` | 保存录音、模型、精确模型 SHA256 及校准阈值绑定；不能放会在重启时清空的 `/tmp`。 |
| 用户修改官方开关后产生 | `/data/wakeword/official_xiaoai` | 缺省即开启，无需每次启动写默认值；用户修改后才保存。 |
| 上传应用后产生 | `/data/lx06/apps/`、`.appmeta`、应用自己的配置/业务数据 | 用户上传内容必须跨重启保留。干净包没有预装用户程序。管理服务可能先建立空目录。 |
| 小智/豆包安装后产生 | `/data/lx06/xiaozhi/`、`/data/lx06/doubao/` | 各自客户端、配置及身份按需解包；小智 Client-Id 用于保持绑定。仅安装某个脚本时才产生该应用内容；公共音频/灯光组件仍由固件提供。 |
| 启动管理与恢复 | `/data/lx06/keeper/`、`user/`、`.bk/`、`autostart` | 保存程序权限/登记、回退和安全模式状态，避免坏脚本重启后反复运行。部分为空目录，部分按操作或故障生成。 |
| 故障诊断 | `/data/lx06/logs/` 的恢复/崩溃记录；`lx06-log.conf`、`lx06-log-seq` | 重启后仍能解释故障原因；日志回传配置可在 Web 修改。日常 Web/SSH/wake 日志已移到内存。 |
| 官方数据 | 配网、账号、设备状态等官方目录 | 官方功能依赖，不能当作自定义程序残留删除。 |

保留旧 DATA 刷写不会自动删除已有用户文件。刷机程序的清 DATA 选项会清除配网、录词等数据；本次打包没有执行刷机或清 DATA。

## 内存中的临时内容

- `/tmp/lx06-wake.log`：监听、录词、回放日志，Web 原位轮转，监听脚本在流异常时也检查 64 KiB 上限。
- `/tmp/lx06-ww-record-state`：录音进度。
- `/tmp/lx06-logs/.webd_session`：Web 登录令牌，设备重启后需要重新登录；修改后的密码仍保留。
- `/tmp/lx06-logs/`：Web 请求、Web 服务、SSH 认证日志，保留原有轮转机制。
- `/tmp/lx06-ssh-apply.log`：本次认证装配日志。
- 采集 FIFO、音频处理中间文件、进程锁和用户应用运行日志也使用 `/tmp`。
- 灯光只使用会话继承的内存通道，不生成 DATA 状态，也不新增常驻服务或定时查询。
- 豆包长回复采用 `/tmp` 中按需创建并立即 unlink 的压缩分片，用后释放，单片最多 256 KiB、总上限 4 MiB；小智使用固定播放队列，不随回复长度增加 DATA 文件。TMP 占用 RAM，受内存保护限制。

不迁移/删除在线设备的旧日志和用户文件；以上变更在新固件启动后生效。

## 为什么选择 MFCC

MFCC 用短时频谱、Mel 滤波和倒谱提取声音特征，再用 DTW 比较录入模板；本版使用去 c0、32 维倒谱提升、较窄 DTW 搜索带和连续窗口确认。它不是早期 13 维 MFCC v4，模型/阈值不可混用。

Embedding 通过神经网络提取向量。训练合适时可具有更好的跨说话人、环境泛化能力，但效果取决于模型与训练数据，运行成本也取决于网络和设备。

本项目选择 MFCC 的依据是当前 LX06 上已有验证：冻结阈值后，实机 shadow 在歌曲/脱口秀/电视混合背景中各 4/4 命中；所测纯背景歌曲 50 秒、脱口秀 50 秒、电视 180 秒零事件。同一合成音色的语速/音量组合 10/10 命中；检出回传相对源语音结束 p50 0.494 秒、p95 0.558 秒，包含 SSH/播放器启动误差，不等于完整云会话就绪时间。

MFCC ARM 单文件评分约 0.01–0.03 秒，之前 INT8 实验约 0.905 秒；这只是离线文件评分，不能称为唤醒速度快 30 倍。短时 8 秒采样 MFCC 约 1.86% 单核 CPU、460 KiB RSS，也不能代表长期峰值。

这些数据支持当前选择，不证明 MFCC 普遍优于 Embedding，也不保证任意电视节目零误触。真人、更多独立节目、空间多声源和新固件启动仍待验收。Embedding FP32→INT8 的已有同样本最大距离漂移约 0.001243，若以后切回 INT8 必须重跑 compare、独立校准，不能沿用 FP32 或 MFCC 阈值。

固件仅内置程序，不把本次测试者的模型或阈值作为所有人的默认值。rc6 新增独立自动校准工具，复用同一版 MFCC 特征和距离计算，不修改常驻检测程序。录满 3 条后，以及以后增删录音时，自动训练、计算阈值并绑定精确模型哈希；更改官方/脚本链接不会撤销校准。

rc9 将两类检查分开：录音间交叉比较用于一致性检查，上限仍为 0.35；唤醒门限由完整模型的实时检测计算，覆盖每条录音、连续三个窗口和四种起始相位，取最差需求再加 10% 与 0.01 的容差，上限仍为 0.35。原版把交叉比较也加上实时容差，导致完整真人录音被误拒绝，现已修正。用户仍可手调；下次增删录音会按新模型重新生成预设。实机本轮“小智你好”四条录音得到 0.301325，“贾维斯”四条得到 0.337823，只对应这两组录音，不是通用默认值。计算兼顾录音覆盖，不能证明任意电视噪声零误触，仍需负样本验收。

录词终态说明继续存 `/tmp/lx06-ww-record-state`，直到下一次操作覆盖或设备重启；繁忙态仍有超时检查，没有新增 DATA 诊断文件。

自动校准工具与训练脚本固化在 `/usr/lib/lx06/wakeword/`；临时运算文件放 `/tmp` 并自动清理，DATA 仍只保存用户录音、模型和配置，没有新增常驻程序或日志目录。设备信息统一通过 `/api/core` 获取，刷新按钮内显示 5 秒倒计时，CPU/内存独立刷新按钮已移除。
