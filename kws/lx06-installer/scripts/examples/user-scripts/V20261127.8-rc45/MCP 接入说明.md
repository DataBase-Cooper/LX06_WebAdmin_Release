# 小智后台 MCP 任务查询

小智的「MCP 自动查询」默认开启，网关随任务提供查询指令。任务可以各用各的指令，例如「查询工单 {id}」或「报告 {id} 什么时候完成」。`{id}` 会替换成该任务的编号。Web88 的「备用查询指令」可留空，供仍使用旧接入方式的网关使用。

## MCP 网关接入

网关提供一个快速返回的后台启动工具，以及一个可反复查询的状态工具。智能体需要知道如何把配置的查询指令映射到状态工具。状态工具在运行中返回简短进度，在完成或失败后返回实际结果。

使用已有的管理连接，例如 SSH，在音箱上调用脚本。网关收到启动任务的工具调用时，读取并保存当次会话标识。此任务的每次状态更新都使用同一个标识。以下是 Web88 上传后的脚本路径。

```sh
script=/data/lx06/apps/xz_watch.sh
session=$(/bin/sh "$script" --mcp-task-session) || exit 1
/bin/sh "$script" --mcp-task-state "$session" order_132 running '查询工单 {id}'
# 后续通知沿用任务启动时保存的 session
/bin/sh "$script" --mcp-task-state "$session" order_132 ready '查询工单 {id}'
/bin/sh "$script" --mcp-task-state "$session" order_132 queried
```

- `running` 表示任务已被网关接收。运行期间约每 30 秒刷新一次。
- `ready` 表示状态工具现在能返回终态，包括任务失败。收到终态查询前可继续刷新。
- `queried` 表示状态工具已把终态结果返回给小智。查询工具应继续保留该结果，供用户手动复查。

首次提交任务时传入该任务的只读查询指令，后续刷新可以省略。指令是一行最多 160 字节的文本，由接入方从相应工具的配置中选取。任务一直没有提供指令时，才使用音箱里的备用值。

接入多台音箱时，将发起音箱与会话标识一起存到任务记录，后续更新通过发起音箱的管理连接投递。若小智网关无法从请求区分设备，可以为各音箱使用独立的智能体接入点。每次会话可同时跟踪 8 个任务。各任务使用不同编号，编号最多 48 字节，可用字母、数字、下划线和连字符。状态快照写入临时目录，超过 90 秒未刷新会失效。网关收到退出码 `75` 时可以稍后重试登记，仍要使用原会话标识。接入方负责认证管理连接及后台任务的生命周期。

## 自动查询与播报

运行中的任务各自约每 35 秒查询一次。多个任务同时可查时，先取已完成的结果，再按各自的查询时间处理。每次对话只进行一轮查询和播报。查询文本通过现有的小智会话发送。等待自动查询回复时听到用户讲话，脚本让出本轮回复并恢复收音。已经开始的播报仍可使用原打断词。

后台启动工具应快速返回，避免云端对长时间同步请求超时。主动结束对话或云端断开后，音箱停止自动查询。再次唤醒只处理新会话的任务。后台任务仍由网关维护，原结果可以由用户主动询问。旧会话的更新会失败，网关应停止向音箱刷新该任务。

音箱只通过这个通用状态入口连接网关，与网关运行的模型、MCP 工具命名或任务实现无关。

## 独立脚本通过小爱播报

将 `runtime/model-adapter/mcp_task_watch.sh` 上传到发起任务的音箱。在扩展内填写 MCP Streamable HTTP 地址、工具名称、JSON 参数和最长执行时间。有认证要求时填写访问令牌。普通部署使用 HTTPS。只在本机转发时可以使用 `http://127.0.0.1:端口/路径`。

官方唤醒词保持小爱处理。说「小爱同学」，再说配置的通道词，例如「运行后台测试」。脚本先交给独立后台进程，原语音对话可以结束。后台进程接收 MCP 工具返回的文本，再通过发起音箱的小爱官方 TTS 播报。此脚本每台音箱同时执行一项任务，最长 600 秒。工具应在一次调用内返回最终可播报的 `content` 文本。若工具立即返回任务编号，可以由 MCP 网关将后台状态等待封装成此脚本可调用的工具。
