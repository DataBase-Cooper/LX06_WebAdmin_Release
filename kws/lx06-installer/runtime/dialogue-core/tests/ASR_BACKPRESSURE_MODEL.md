# Capture → ASR backpressure: offline model only

Run `python runtime/dialogue-core/tests/test_asr_backpressure_model.py -v`. This is a single-threaded abstract model, not actual capture, ASR, sockets, SDK, acoustic or device acceptance. No production behavior is changed.

## Contract explored

The pending FIFO owns up to 128000 bytes (4 seconds at 16 kHz mono s16le); a separate owned frame holds at most 960 bytes. Admission is atomic. ACCEPTED and HELD_BACKPRESSURE transfer ownership; HELD means the exact current frame was copied but further upstream admission must stop. REJECTED_BACKPRESSURE transfers no ownership: caller must retain/retry the same data, or account and explicitly report a discontinuity. Rejection counters in the model count attempts, not unique or lost audio. When pending space opens, the held frame moves to the tail before any subsequent admission. Stop closes admission but keeps accepted bytes until explicitly drained; a latched incident survives late flushing. Production needs an explicit terminal result for a stop that cannot drain, with exact retained/undelivered accounting and a user-visible failure, not a silent cleanup.

The synthetic feed fills the entire four-second FIFO, captures the next 960-byte frame into owned storage, mutates its original borrowed buffer, offers 125 further frames while blocked, stops, and drains and compares every accepted frame in order. Further tests cover partial drains, repeated overflow, variable frame sizes and invalid admission. This models a producer that sees every rejection; it does not guarantee preservation of rejected input or audio never offered.

## Why not ship

`main.c:capture` receives a frame from `dc_io_capture_next`, processes it into stack `pcm`, then calls ASR and possibly the audio route. `control_asr.c:defer_audio` currently evicts oldest pending bytes and returns no overflow status. The recursive pending drain clears queue bookkeeping before encoding/sending, so a later send/encode failure cannot currently promise retained undelivered bytes. ASR and route are two distinct consumers: retry must not duplicate ASR or skip the route, and source binding/voice effects must occur exactly once. Protect-off and close clear state; stop/late flush behavior must be redesigned together.

Capture reads datagrams with `recvmsg`; merely suspending reads after holding a frame provides no proven end-to-end backpressure to microphone hardware or producer. Kernel/producer queues can fill and upstream loss must be detected by reliable sequence and producer-status semantics, including resets, gaps, restarts and overflow while stopped. This model has no asynchronous producer, real socket pressure, concurrency, failure, durable retention, authenticated user status, or retry timeout. Exact physical lost-audio length cannot be inferred from rejected offer attempts or an unavailable upstream capture interval. Unbounded live input and bounded storage cannot guarantee lossless retention under an indefinitely stalled consumer.

Before integration, establish an owner that retains PCM and metadata across retries, transactional per-consumer completion, bounded queues at each layer, a drain/abort deadline with explicit undelivered counts, and an authenticated status channel tested through the actual account wrapper/supervisor/UI. Also solve provenance/mixed utterance ambiguity documented in `SOURCE_SPAN_PROTOTYPE.md`: preserving bytes alone does not safely identify the next sentence or prevent stale interruption. Exercise actual adapter, capture, route and stop/late-flush under synthetic pressure and fault injection; then independently establish live acoustic behavior. Until then do not substitute fail-close that silently loses the next sentence or claim user notification.
