# Deferred ASR provenance: offline model and production blocker

Run `python runtime/dialogue-core/tests/test_source_span_prototype.py -v` from the installer root. This is an abstract Python model, not a replacement for any C component and not recognition, transport, capture, acoustic, or device acceptance. The existing `PENDING_SOURCE_BLOCKER.md` documents the independently runnable production adapter → recognition → session RED. A fresh ASan/UBSan run reported `pending-old-reply=1, recognized-reply=2, serial=2, cancels=2, current-live=0` and exit 1. Peer text is synthetic and the stop callback is only a counter.

## Model contract

Each immutable byte span carries a reply generation, trustworthy speech/quiet/unknown classification, and a trustworthy speech-boundary/utterance identity; missing evidence is unknown, never inferred from the current reply. Queue append is atomic and bounded, with explicit overflow rather than silent eviction. A decoder FINAL does not delete pending input. Proven distinct utterance boundaries allow the old utterance and following user sentence to be drained separately, in byte order. A result can drive interruption only when all speech attributed to its decoder result is unambiguously from the current live generation; stale, unknown, mixed or silence-only is rejected. A future sentence with its own proven boundary remains available. The model demonstrates this with synthetic labels and a synthetic counter, not the actual session.

An unknown boundary cannot safely promise next-sentence preservation *and* a clean split: the model consumes the available unsplittable region as ambiguous; this needs an explicit user-visible failure/retry policy, rather than silent loss. Similarly, overflow must fail the owning session visibly or apply backpressure without discarding bytes. The model does not implement such user notification or bounded wait/recovery. Quiet-span exclusion is sound only if quiet classification is itself trustworthy; ordinary VAD absence of detected speech is not such proof.

## Why not a production patch

Current capture stamps processing-time current reply (`main.c:213`) rather than provenance of each sample; queued capture, voice guard, incomplete 640-byte Opus frames, SDK endpointing and cloud decoder do not establish trustworthy independent utterance boundaries or certify silence. `bind_source` binds the active, possibly already-ended decoder after feed, while new PCM is deferred and `start()` clears the binding. The pending ring drops old bytes on overflow. Its drain recursively mixes spans into one encoder/decoder; partial and final text provide no alignment proving which PCM produced each word. A per-span generation alone cannot identify a result once mixed, and a later mixed span could invalidate a partial after an irreversible stop. A source generation is not an independent speech boundary; two sentences may be spoken while one reply owns playback.

A deployable solution must specify capture-time identity versus delayed frames; trustworthy split/unknown semantics; partial-action admission before future audio; all byte/frame/ring split and overflow cases; final, timeout, cancel, replay/archive, rollover, outbox backpressure, TTS hold/yield and both CONTROL/QUESTION profiles; session and route final-serial behavior; valid next-question retention and explicit failure. It must exercise the real adapter/recognition/session path for these branches, plus synthetic decoder evidence distinguished from real acoustic acceptance. No source flush, simplistic generation reassignment, or production change was made because these guarantees have not been established.
